# Phase 4 小片 5：微信草稿流程实施计划

> 状态：已完成
> 范围：只在现有 SightSync Android App 内实现“找到唯一联系人并填写草稿”，停在最终发送前。
> 安全边界：不打开微信、不点击发送、不把发送动作放入确认队列、不调用远端 AI、不读取截图、不处理不唯一候选。

## 目标与验收边界

本小片实现显式微信草稿命令，例如“在微信给张三写草稿：明天见”。命令只有在微信已经位于前台时才执行。执行器最多完成四个白名单动作：必要时点击唯一搜索入口、填写联系人、点击唯一精确联系人、填写消息草稿。每个动作都必须重新采集无截图页面上下文并校验包名和节点。

完成后必须停在聊天输入框，不定位、不点击“发送”，并播报“请确认内容并手动发送”。候选缺失、候选不唯一、包名变化、页面不稳定、风险页面、动作失败、超时或取消均停止后续操作。

## 非目标

- 不从其他 App 自动打开微信。
- 不支持群发、多个联系人或模糊联系人选择。
- 不点击发送，也不允许用户语音“确认”后由本小片发送。
- 不新增动作类型，不放宽 `AgentPlan`、动作白名单或风险规则。
- 不通过截图、OCR、坐标点击、脚本或远端计划完成流程。
- 不为测试加入生产环境命令注入入口。

## 设计

### 明确命令解析

新增 `WeChatDraftCommandResolver`。只接受明确包含“微信”的固定句式：

- `在微信给<联系人>写草稿：<消息>`
- `在微信给<联系人>准备消息：<消息>`
- `给<联系人>写微信草稿：<消息>`

联系人限制为 1 至 40 个 Unicode code point，消息限制为 1 至 500 个 code point。看起来像微信草稿命令但字段缺失或超长时返回本地错误，不回落到远端 AI；普通聊天、打开微信和其他 App 命令返回 `NotCommand`。

### 唯一节点定位

新增 `WeChatDraftNodeLocator`：

1. 搜索入口优先选择语义包含“搜索/search”的唯一可编辑节点，否则选择其唯一可点击且非可编辑祖先。
2. 联系人只接受标签与目标联系人规范化后完全相等的唯一可点击节点；多个同名联系人直接停止。
3. 消息输入框优先选择语义包含“消息、输入、聊天、message”的唯一可编辑节点；语义不足时只允许页面上恰好一个可编辑节点的保守回退。

所有候选按 `nodeId` 去重，不使用模糊首选，不定位发送控件。

### 有界任务执行

新增 `WeChatDraftTaskRunner`，仅接受包名 `com.tencent.mm`，总超时 60 秒、最多四个动作。每个动作使用现有 `AgentPlanExecutor` 执行一个两步小计划：`ACTION` 后接 `VALIDATE_PAGE` 或 `WAIT_FOR_UI`。每次页面转换后重新采集 `collectForValidation()`，包名必须仍为微信。

执行顺序：

1. 如果搜索入口不可编辑，点击唯一入口并重新定位。
2. `SET_TEXT` 填写联系人。
3. 重新采集并点击唯一精确联系人。
4. 重新采集并 `SET_TEXT` 填写消息草稿。
5. 返回 `DraftReady`，Session 只播报人工确认提示。

执行器自身不生成 `CLICK_NODE` 发送动作，也不把发送动作存入 `ConfirmationManager`。

## 预期风险

- 微信不同版本和无障碍节点语义可能不同；本小片宁可停止，也不通过坐标或模糊猜测继续。
- 模拟器可能未安装或未登录微信，因此自动化测试与 App 冷启动可完成，但真实微信端到端验收可能需要已登录的专用测试设备。
- 草稿写入本身会改变输入框内容，但不会产生外部发送副作用；最终发送必须由用户人工确认和操作。
