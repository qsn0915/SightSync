# Phase 4 小片 6：阶段验收计划

日期：2026-06-27

## 目标

验收 Phase 4「低风险受限多步 Agent」是否满足进入 Phase 5 的门槛。验收只覆盖已实现的受限多步能力：浏览器搜索、App 内导航、微信草稿，以及通用计划执行器的中断/确认边界。

## 范围

### 必须验证

1. 成功路径：受限多步任务只能由明确用户指令触发，并按白名单动作执行。
2. 页面变化中断：页面状态变化、目标丢失、超时或连续失败后停止后续步骤，并给出可理解原因。
3. 高风险确认：高风险或待确认步骤不能静默执行。
4. 用户主动停止：用户停止后，不再执行后续步骤。
5. 微信草稿边界：只填写草稿，不点击发送，不创建可执行的发送确认。
6. 后端代理必须启动，App 通过本机代理路径完成可用性检查。

### 不允许做

1. 不替用户接受浏览器、微信或其他第三方 App 条款。
2. 不发送微信消息、不点击支付/提交/删除等高风险动作。
3. 不清除真机数据、不卸载 App、不修改系统设置，除非用户另行明确要求。
4. 不进入 Phase 5；验收结论出来后先交给用户确认。

## 前置检查

1. 查看 `git status --short`，确认工作区已有 Phase 4 改动，验收不回滚、不提交。
2. 启动后端代理：
   - 工作目录：`backend`
   - 命令：`npm start`
   - 默认端口：`8787`
   - 默认 token：`dev-token`，除非环境变量中另有配置。
3. 对连接设备配置：
   - `adb reverse tcp:8787 tcp:8787`
   - 安装当前 debug APK。
   - 启动 `com.sightsync.assistant/.MainActivity`。

## 自动化验证

1. 后端：
   - 清空测试进程中的 `AI_API_KEY`、`AI_PROVIDER_URL`、`AI_MODEL`。
   - 运行 `npm test`。
2. Android：
   - 运行 `.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug`。
3. 静态安全检查：
   - `git diff --check`。
   - 扫描 Phase 4 微信草稿生产代码中是否存在点击发送相关实现。

## 真机/设备验收

### 基础启动

1. 识别连接设备。
2. 覆盖安装 debug APK。
3. 启动 App。
4. 检查前台 Activity、进程 PID、最近 logcat 中 SightSync 崩溃/ANR。

### 后端代理

1. 通过电脑本机请求 `http://127.0.0.1:8787/v1/health`。
2. 通过 `adb reverse` 确保设备访问 `127.0.0.1:8787` 能回到电脑代理。
3. 如果 App 内配置仍需用户手动填写代理地址/token，只记录状态，不擅自改用户设置。

### 四类场景

1. 成功路径：
   - 优先使用已初始化浏览器或系统设置页执行低风险导航/搜索验证。
   - 微信仅在设备已安装并登录微信时验证草稿填写；验证必须停在草稿，不发送。
2. 页面变化中断：
   - 依赖单元/集成测试覆盖通用执行器的页面变化、目标丢失、超时、连续失败停止。
   - 如设备允许，补充一个真实页面变化观察。
3. 高风险确认：
   - 依赖自动化测试和源码扫描确认待确认/高风险步骤不静默执行。
   - 真机不执行支付、发送、提交、删除等动作。
4. 用户主动停止：
   - 依赖自动化测试覆盖取消/停止状态清理。
   - 如设备允许，启动 App 后检查停止入口可见性；不破坏用户当前设置。

4. 汇报测试结果、设备验证结果、风险、下一个小片。
